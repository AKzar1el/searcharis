# Offline Cloudflare Pages `_headers` parity gate

Use this **opt-in local build check** to prevent a compiled static Cloudflare
Pages build from accidentally dropping a reviewer-approved `_headers` file.
That file can contain SEO-sensitive `X-Robots-Tag` directives (for example,
`noindex` on static `*.pages.dev` preview hosts), as well as other response
header configuration. The checker does not access Cloudflare or fetch a URL.

## Reproducible pass and regression

From the repository root (Python and `uv` installed):

```sh
uv run python -m searcharis.headers_policy_cli \
  examples/seo-contract/headers-policy/reviewed.txt \
  examples/seo-contract/headers-policy/passing --json
# Exit 0: built _headers matches the reviewed reference exactly.

uv run python -m searcharis.headers_policy_cli \
  examples/seo-contract/headers-policy/reviewed.txt \
  examples/seo-contract/headers-policy/drifted --json
# Exit 1: a review-critical header rule was removed in the compiled artifact.
```

Use your *actual final static build output directory* and a separately
reviewed, source-controlled `_headers` file outside that build:

```sh
uv run python -m searcharis.headers_policy_cli policies/approved-headers.txt dist
```

On Windows PowerShell 5.1 and 7, the command is the same, on one line.
Preserve its process exit code in CI:

- **0**: exact byte-for-byte match, including comments, order, and line endings.
- **1**: root `_headers` missing or changed. Fail the release gate; review the
  compiled artifact and policy intentionally before updating the reference.
- **2**: invalid/unreadable input, unsafe built symlink, incorrect reference
  placement, or oversized file. Do not treat this as a passing check.

`--json` emits a machine-readable object with `status`, `artifact`,
`reason`, and SHA-256 digests, without disclosing policy content. For a
portable artifact, use `--json-file PATH` instead to write that same complete
result directly as UTF-8, including on Windows PowerShell 5.1. The destination
must be a new file with an existing parent directory outside the compiled
build; the command never overwrites an existing report. For example:

```sh
uv run python -m searcharis.headers_policy_cli policies/approved-headers.txt dist --json-file reports/headers.json
```

Pass (exit 0) and drift (exit 1) reports are retained for CI consumers;
invalid input (exit 2) creates no report. An interrupted file write receives
identity-checked best-effort cleanup, not an atomic write guarantee. Preserve
the command's exit code and never turn an exit 1 or 2 into success.

The verifier bounds each local file read to 8,500,000 bytes, requires exact
case of the build-root `_headers` name even on NTFS, and rejects built
symlinks and a reviewed file inside the build. It **does not validate syntax**,
render the effective applied header rules, or prove that a specific response
received `X-Robots-Tag`. Whitespace-only changes intentionally fail; update
the reference only after review.

**Cloudflare Pages limitation:** `_headers` rules apply to responses for
**static assets**, not responses generated by **Pages Functions**, SSR or a
`_worker.js` route. Those require response headers in the Function/Worker
itself. Multiple matching header blocks can join values, and redirects take
precedence. A green byte comparison is not a live HTTP or indexing assertion.
External Cloudflare rules, deployments, security settings and cost boundaries
are outside this check.

Source: [Cloudflare Pages custom headers](https://developers.cloudflare.com/pages/configuration/headers/)
(updated November 12, 2026), and
[Pages redirects](https://developers.cloudflare.com/pages/configuration/redirects/).

This is a local pre-deployment test only. It neither deploys the application nor
modifies configuration, credentials, schedules, or CI workflows.
